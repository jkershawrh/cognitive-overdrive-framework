# Rehearsal and iteration

The presenter arc adapts Campbell into seven beats: ordinary world, call, guide, threshold, trials, reward, return. The viewer is the hero; the engineer provides a way to understand and act.

## Before presenting

- Run `npm run check` and `npm run test:visual`.
- Preview at 1920×1080 and 1440×900, then check a narrow viewport. Desktop chapters must fit a single screen. Dialogs and evidence history may scroll internally.
- Test every architecture reveal and all three policy conditions. Missing evidence and absent authority must stop the handoff. All records retain the SIMULATION label.
- Play Kersh narration from a user gesture. Check transcript, pause, chapter changes, and the individual audio files. The generation profile is preserved; likeness and delivery require the owner's listening review.
- Inspect Red Hat platform alignment and the separate Intel, AMD, NVIDIA, and Arm evidence states. Local, historical, and pending evidence must stay distinct.
- Open Launchpad, AERIS, Edge, Cost-Aware/CPU Bake Off, and Triforce cases. Research concepts must retain that status.
- Use arrow keys, Home, P for presenter prompts, F for fullscreen, and the explicit close. Browser back and chapter deep links must work.
- Keep the source walkthrough and simulation separate from any future live adapter. No current live cluster is contacted by the app.

## Journey acceptance

Presentation: seven chapters. Audience lens: four decisions with corresponding case emphasis. Architecture: source-linked questions and staged boundaries. Proof: three local policy conditions with persistent session records. Reuse: Launchpad and learning paths. Handoff: project evidence drawer, public source where available, explicit presentation close. Hands-on: continue into the selected project's own lab; this portfolio does not certify those environments.
